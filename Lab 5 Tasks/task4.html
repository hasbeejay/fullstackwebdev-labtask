04 / NOTES

Requirements & explanation

Requirements covered

Person with name, email and introduce()
Student adds rollNo, marks, getResult(); FacultyMember adds employeeId, department
Both subclasses override introduce() and reuse the parent through super
Mixed array run with users.forEach(user => console.log(user.introduce()))
call() with the guest speaker object as this
Detached const fn = student.introduce investigated, then fixed with bind()

Concepts demonstrated

ConceptWhat happens in the code
constructor / newnew Student(...) creates an empty object, sets its prototype to Student.prototype, runs the constructor with this pointing at it, and returns it.
extends / superclass Student extends Person links the prototype chains. super(name, email) must run before this is used; super.introduce() calls the parent method.
Method overridingStudent and FacultyMember define their own introduce(), which shadows Person.prototype.introduce.
Runtime polymorphismThe same user.introduce() call runs a different method depending on the actual object in the array, decided when the call happens.
instanceofWalks the prototype chain: a Student is a Student and a Person, but never a FacultyMember.
call()Runs Person.prototype.introduce once with guest as this. The guest only borrows the method; it is not a Person.
Detached methodfn() has no object before the dot, so this is undefined (class code is strict) and reading this.name throws a TypeError.
bind()Returns a new function whose this is permanently fixed, so it is safe to pass around. Even .call(otherStudent) cannot override it.

Why the detached call fails

this is decided by how a function is called, not where it was written. student.introduce() has an object before the dot, so this is that student. const fn = student.introduce; fn() copies only the function, and the plain call has no object. In sloppy mode this would fall back to the global object and print "undefined" for the name; in strict code it is undefined and the property read throws.
